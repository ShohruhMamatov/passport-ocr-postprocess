# Отчёт: постобработка OCR паспорта РФ

## Прогноз по test

**Примем 608 из 2000 документов (30,4%). Ожидаемое число принятых с ошибкой — около 6** (95%-ная верхняя граница — около 11).

Как считали: доля ошибок среди принятых на train по каждому источнику, умноженная на число принятых на test из этого источника.

| source | train: принято / с ошибкой | доля ошибок | test: принято | ожидаемо ошибок |
|---|---|---|---|---|
| web | 461 / 5 | 1,08% | 253 | 2,7 |
| mobile | 319 / 1 | 0,31% | 211 | 0,7 |
| mobile_v2 | 102 / 2 | 1,96% | 144 | 2,8 |
| **итого** | **882 / 8** | 0,91% | **608** | **≈ 6** |

Верхняя граница: 8 ошибок на 882 принятых дают по Пуассону 95%-ную верхнюю оценку доли 1,64%, то есть ≈ 10–11 ошибок на 608. Пороги подобраны на том же train, поэтому оценка скорее оптимистичная.

## Что выяснил о данных

1. **Сырой вывод модели плох.** Все 10 полей верны только у 56% документов train. Больше всего ошибок в `Issue_organization_ru` (602) и `Birth_place_ru` (519). Эти поля не дублируются в MRZ.
2. **MRZ — главный источник проверки.** Вторая строка MRZ содержит серию и номер, дату рождения, пол, дату выдачи и код подразделения, защищённые контрольными цифрами (веса 7-3-1). Первая строка содержит ФИО в транслитерации (Ч→3, Ш→4, Я→8, Й→Q, Ь→9 …).
3. **Детектор теряет строки** многострочных полей: рамка поля высотой ~59 px при одной прочитанной строке ~29 px. Распознанный текст при этом выглядит правдоподобно и уверенно.
4. **Уверенность `mobile_v2` откалибрована иначе.** Почти все символы идут с conf ≥ 0,999. Среди символов с conf 0,99–0,999 ошибочны 11% (у web — 0,14%), а при conf ниже 0,99 — почти все. Один общий порог здесь не работает. В test доля `mobile_v2` заметно выше (431 против 292 на train), поэтому это важно для итогового результата.
5. **Справочник подразделений** не совпадает с разметкой дословно (`ОБЛ.` / `ОБЛАСТИ`, разные редакции названий). Подстановка названия по коду дала бы ошибки, поэтому справочник используется только как словарь допустимых слов.
6. **MRZ хранит год двумя цифрами**, поэтому ошибка века (`1091` вместо `1991`) проходит сверку. Нужна отдельная проверка правдоподобия года.
7. **Остаточные ошибки — «уверенные».** Модель исправляет необычную строку на частотную (`КИТУРКС` → `КИТУРКО`, `ФАРИЛА` → `ФАРИДА`), и MRZ читается с той же ошибкой. Уверенность это не ловит: conf таких символов 0,99–1,0.

## Алгоритм (`postprocess.py`)

Документ принимается, только если пройдены все проверки:

1. Все поля найдены детектором. Отчество может отсутствовать — пустое отчество есть и в разметке.
2. **Сверка с MRZ.** Если все контрольные цифры MRZ сходятся, номер, даты, код и пол из визуальной зоны должны совпасть с MRZ точно, а транслитерированное ФИО — со строкой 1 (с учётом обрезки до 39 символов). Если MRZ нет или контрольные цифры не сходятся, требуется более высокая уверенность по этим полям.
3. **Потерянные строки.** Число строк поля должно соответствовать высоте рамки поля.
4. **Пороги уверенности по источнику** (минимальная conf символа, подобраны перебором на train):

   | source | поля, сверенные с MRZ | без MRZ | место рождения / кем выдан |
   |---|---|---|---|
   | web | 0,50 | 0,99 | 0,97 |
   | mobile | 0,50 | 0,95 | 0,97 |
   | mobile_v2 | 0,999 | 0,999 | 0,999 |

5. Каждое слово в «Кем выдан» должно встречаться в справочнике подразделений.
6. Проверяются форматы (`NN NN NNNNNN`, `NNN-NNN`, `МУЖ.`/`ЖЕН.`) и правдоподобие годов.
7. **Действительность на 01.10.2026.** Паспорт выдан не раньше 14 лет и не позже даты проверки. Паспорт подлежит замене в 20 и 45 лет и считается недействительным через 90 дней после соответствующего дня рождения. Выданный после 45 лет действует бессрочно. Это правило отклонило 27 документов train и 12 документов test. `evaluate.py` его не учитывает.

Вклад шагов на train: только сверка с MRZ и порогами — 893 принятых, 31 ошибка; с проверкой потерянных строк и годов — 9 ошибок; с порогами по источнику — 882 принятых, 8 ошибок.

## Что можно улучшить

- **Исправлять, а не отклонять.** 309 документов test отклонены из-за расхождения с MRZ. Если контрольные цифры MRZ сходятся, цифровые поля можно брать из MRZ. Это главный резерв числа принятых.
- **Честная оценка:** подбор порогов на одной половине train и проверка на другой (кросс-валидация).
- **Против «уверенных» ошибок в ФИО:** словари имён и отчеств, проверка согласования отчества с полом.

## Запуск

```
python postprocess.py data/test_predictions.jsonl answers.jsonl   # решение (CPU, без интернета, только stdlib)
python evaluate.py train_answers.jsonl data/train_labels.jsonl    # проверка на train
python tune.py [--sweep]                                          # диагностика и перебор порогов
```
